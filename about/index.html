About This Workflow

Last updated:

The goal: the CPA does only the high-value tasks. Administrative staff or a machine does all other tasks. This page tells how we design the workflow to get there.

The Idea: A Pin Factory

Adam Smith described a pin factory. One worker who makes a complete pin makes few pins each day. Ten workers who each do one small step make thousands of pins each day.

Today our CPAs are expensive artisans who also do factory-floor tasks. We break each stage into smaller and smaller tasks. Then we give each task to the least expensive person or machine that can do it correctly.

Sort Every Task with One Test

Ask this question about each task: can I write the rule so that a new employee with no tax knowledge gets the same answer as the CPA?

J · Judgment  No. Only the CPA does it. R · Rule  Yes. Administrative staff do it with a checklist. M · Machine  Yes, and all inputs are digital. A bot is a candidate. Client  The client does it. We can make it easy, but we do not control it.

Split a task until each part has one level only. If a task mixes J and R, make two tasks. Many CPA tasks today are 10% judgment and 90% rule. When we split them, the CPA keeps the 10%.

Every Task Leaves Evidence

It is not enough for a person to say “yes, that is right.” Each task must leave a concrete record that shows it happened and shows its result. A reviewer, an auditor, or the next worker on the line can then see the record without asking anyone.

This applies most of all to J tasks. Judgment that leaves no record cannot be checked, measured, or taught.

Decision: Yes, No, or Other.

Explanation: required for Other. Recommended for No.

Who and when: the CPA's initials and the date.

Where: on the item itself (the Request List line, the workpaper line, the checklist question), not in an email or in a person's memory.

A3, Generate Request List. The CPA does not only “look at” the Baseline report. Each Baseline line carries a mark: Ask, Do not ask, or Other. Each Do not ask and each Other carries a reason, the CPA's initials and the date. A4 can then check the marks without asking the CPA anything.

The record is the handoff. When the J task leaves a record, the next task can be R or M, because the next worker reads the record and does not need to understand the judgment.

Exceptions Go to the CPA

A factory line works for the standard case. Do not try to write a rule for every unusual case. Each task card has an exit: “If X, send to the CPA.”

The CPA's work then has two parts: the J tasks and the exceptions. Count the exceptions. When one type of exception occurs many times, write a rule for it. It then becomes an R task.

The CPA Touch Map

The high-level view is a grid. The columns are the nine stages. The rows are CPA, Admin, Bot and Client. Each cell shows the number of tasks, and the minutes when we know them.

Today the CPA row is full. The goal is a CPA row that is almost empty, with only the J tasks and the review gates. The stage with the most CPA minutes is the next stage to work on.

Manage the Project with a Status on Each Card

  1. Draft: written.
  2. Reviewed: the person who will do the task agrees that the card is correct.
  3. Tested: used on one real return.
  4. Standard: used on all returns.

The weekly review asks two questions: which cards moved, and which cards are stopped?

Two Cautions

A handoff adds a queue and a chance to lose the item. Split a task only if the time saved is more than the cost of the handoff. Adam Smith's workers stood next to each other. Our workers and bots do not.

Use 3 to 5 simple returns in December and January. A task card is a guess until a real return goes through it.

Today the cards are written in files that make these web pages. That works for dozens of cards. It will not work for hundreds.
